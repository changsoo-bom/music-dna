### 상태 관리 분리

**데이터 종류마다 사는 곳이 다르다.**

| 데이터 종류 | 도구 | 위치 |
|-------------|------|------|
| Spotify 응답 | 서버 컴포넌트 + ISR | `lib/spotify/` |
| 계산된 리포트 지표 | 서버 컴포넌트 | `lib/report/` |
| 기간·장르 필터 | **URL `searchParams`** | 라우트 |
| 클라이언트 전용 UI (툴팁 좌표, 캐러셀 위치, 네비 열림) | **Zustand** | `lib/use-{domain}-store.ts` |
| 무한스크롤 페칭 | **TanStack Query** | `hooks/` |

#### 기본은 서버 컴포넌트

조회는 서버 컴포넌트에서 직접 가져온다. 클라이언트 페칭이 기본이 아니다.

#### 서버 데이터를 Zustand에 복사하지 않는다

**동기화 지옥의 원인이다.** 리포트 지표를 스토어에 넣는 순간 언제 갱신할지를 손으로 관리해야 한다.

#### 차트 인터랙션 상태

호버·툴팁·캐러셀 위치는 **해당 컴포넌트의 로컬 state**로 충분하다. 전역으로 올리지 않는다.
여러 차트가 같은 호버를 공유해야 할 때만 Zustand를 꺼낸다.

#### 판단 흐름

```
데이터가 서버에서 온다        → 서버 컴포넌트 (기본값)
  └ URL로 표현되는 상태다     → searchParams
  └ 클라이언트에서 이어붙인다 → TanStack Query
데이터가 서버와 무관하다      → 로컬 state → (공유 필요) Zustand
```

Zustand 스토어는 인터페이스를 먼저 정의하고 `create<T>()` 제네릭을 쓴다.
스토어명 `use{Domain}Store`, 파일명 `use-{domain}-store.ts`.
